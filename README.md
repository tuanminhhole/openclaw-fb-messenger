# fb-messenger — Facebook Messenger channel for OpenClaw

Adds **Facebook Page Messenger** as a native OpenClaw channel, alongside Telegram and Zalo.
The plugin only handles inbound/outbound messages — replies are generated by the OpenClaw
agent (and your configured model provider, e.g. **9Router**), exactly like the other channels.

- **Inbound**: a public webhook (`/webhooks/messenger`) receives Meta events, verifies the
  `X-Hub-Signature-256` signature, and dispatches each message to the agent.
- **Outbound**: replies are streamed back through the Graph API (`POST /me/messages`).

## Requirements

- OpenClaw `>= 2026.6.10`.
- A **public HTTPS URL** pointing at your OpenClaw gateway (VPS domain, or ngrok for testing).
  Meta only delivers webhooks over HTTPS.
- A Facebook **Page** and a Meta **App** with the *Messenger* product enabled.

## Install

```bash
# From ClawHub (private, under the tuanminhhole org):
openclaw plugins install clawhub:tuanminhhole/openclaw-fb-messenger
```

## Configure

### 1. Meta App + Page

1. Create an app at <https://developers.facebook.com/apps> → add the **Messenger** product.
2. Under *Messenger → Settings*, generate a **Page Access Token** for your Page.
3. Note your **App Secret** (*App Settings → Basic*).
4. Choose any string as your **Verify Token** (you'll enter the same value below).

### 2. Environment variables

```bash
FB_MESSENGER_PAGE_ACCESS_TOKEN=EAAB...      # Page access token
FB_MESSENGER_APP_SECRET=xxxxxxxx            # App secret (for signature verification)
FB_MESSENGER_VERIFY_TOKEN=my-verify-token   # any string you choose
```

### 3. openclaw.json

```jsonc
{
  "channels": {
    "fb-messenger": {
      "enabled": true,
      "pageId": "<your-page-id>",
      "dmPolicy": "open",          // open | allowlist | pairing | disabled
      "allowFrom": ["*"],
      "historyLimit": 50
    }
  }
}
```

Secrets (`pageAccessToken`, `appSecret`, `verifyToken`) are read from the environment first, so
they don't need to live in `openclaw.json`. You may also place them under the channel if you
prefer.

### 4. Register the webhook with Meta

In *Messenger → Settings → Webhooks*:

- **Callback URL**: `https://<your-gateway-domain>/webhooks/messenger`
- **Verify Token**: the same value as `FB_MESSENGER_VERIFY_TOKEN`
- **Subscription fields**: at minimum `messages` (and `messaging_postbacks` if you use buttons).

The plugin **auto-subscribes the Page to the app webhook on startup**, so you don't need to do
the "Edit Page Subscriptions" step manually. Meta calls the URL with a `GET` handshake; the
plugin answers it automatically once the gateway runs with this channel enabled.

## Verify it works

```bash
npm install
npm run typecheck   # tsc --noEmit
npm run build       # bundle to dist/
npm test            # runtime smoke test of the inbound path (verify + HMAC + dispatch)
```

Then start your OpenClaw gateway and message the Page from a Facebook account.

## Scope

**v1**: 1:1 (direct) text conversations, DM policy/allowlist, signature verification, auto chunking.

**Not yet (v2)**: group/multi-page, quick-reply buttons & persistent menu, proactive
(agent-initiated) sends, reactions, handover protocol.
